# Document management setup

## Implemented API flow

All document endpoints require a Firebase ID token and a verified email.

1. `POST /documents/upload-url` creates a pending database row and returns a short-lived V4 signed GCS PUT URL.
2. The client uploads the bytes directly to GCS. Send both headers returned in `required_headers`.
3. `POST /documents/{document_id}/confirm` checks that the object exists, verifies its stored size and content type, and records the size.
4. `GET /documents`, `GET /documents/{document_id}`, and `GET /documents/{document_id}/status` return only documents owned by the authenticated user.
5. `DELETE /documents/{document_id}` deletes the GCS object and then the database row (including related chunks).

The API currently allows PDF, DOCX, TXT, and CSV. The maximum accepted size is 25 MiB. The object key is generated by the server and scoped under the internal user UUID. The signed PUT URL is valid for 10 minutes and uses a create-only generation precondition so it cannot overwrite an existing object.

## Local configuration

Copy `.env.example` to `.env` and set the local database password. Keep `.env` out of Git.

Authenticate Application Default Credentials:

```bash
gcloud auth application-default login
```

Set `GCS_SIGNING_SERVICE_ACCOUNT` to the service account used to sign URLs. The identity represented by local ADC needs permission to sign blobs as that service account (grant `roles/iam.serviceAccountTokenCreator` on that service account to your local developer identity).

The signing service account needs `storage.objects.create` on the bucket. The API's runtime identity also needs `storage.objects.get` and `storage.objects.delete` for confirmation and deletion. Prefer a bucket-scoped custom role containing only these permissions; `roles/storage.objectAdmin` is a broader development shortcut, not the least-privilege production choice.

Keep the bucket private with public access prevention and uniform bucket-level access enabled.

## Install and run

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open `/docs` to inspect the generated OpenAPI documentation.

## Upload example

First call `POST /documents/upload-url` with a Firebase bearer token:

```json
{
  "file_name": "guide.pdf",
  "content_type": "application/pdf"
}
```

Then PUT the file bytes to the returned `upload_url`, including every key/value in `required_headers`. Finally call `POST /documents/{document_id}/confirm` with the same bearer token.

## Current boundary

Confirmation validates GCS object metadata, not the actual file signature or whether the document is safe to parse. The ingestion worker must validate file signatures and parser limits before extracting content. Cloud Tasks, chunking, embeddings, and ingestion status transitions are intentionally not part of this milestone.
